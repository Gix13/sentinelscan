# SentinelScan product direction

## Purpose

SentinelScan is an educational security-analysis platform and portfolio project. It demonstrates how file-triage and authorized website-assessment signals can be collected, classified, and explained without presenting automated output as a professional verdict.

## Audiences

- Portfolio reviewers evaluating full-stack, security, and machine-learning engineering
- Security learners exploring how heterogeneous signals become understandable reports
- Authorized operators testing integrations in controlled environments

## Experience principles

- **Precise:** make state, scope, evidence, and limitations unambiguous.
- **Credible:** use restrained visual language and concrete technical detail.
- **Restrained:** preserve focus; animation should communicate state rather than decorate it.
- **Safe by default:** lead with synthetic mock mode and require explicit configuration for live integrations.
- **Explain, do not overclaim:** distinguish observed evidence, model predictions, and analyst conclusions.

## Visual direction

The interface should feel precise, credible, and restrained. The dark technical palette, red-to-violet signal gradient, subtle grid, and shield mark are the core identity. Avoid neon “hacker” clichés, fake terminal noise, excessive glow, and alarmist language.

## Accessibility baseline

- Target WCAG 2.2 AA contrast and interaction behavior.
- Respect reduced-motion preferences.
- Keep keyboard focus visible and preserve semantic structure.
- Never communicate severity or status through color alone.

## Portfolio success criteria

A reviewer should understand the project’s purpose, architecture, safe demo path, and engineering depth within a few minutes. The interface and documentation should make the project memorable without obscuring its educational scope or operational limitations.
